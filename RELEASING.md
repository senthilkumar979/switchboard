# Releasing Switchboard

Publishable packages:

- `@switchboard/core`
- `@switchboard/react`
- `@switchboard/devtools`
- `@switchboard/api-mock`

Versioning uses [Changesets](https://github.com/changesets/changesets). Private stubs (`angular`, `vanilla`), apps, examples, and tooling are ignored.

## Prerequisites

1. Repository on GitHub with `main` as the default branch.
2. GitHub Actions enabled.
3. Repository secret `NPM_TOKEN` — an npm automation token with publish rights to the `@switchboard` scope (create the org/user packages on first publish if needed).
4. Local: Node 20+, pnpm 9.

## Everyday flow

1. Land features on `main` via PRs. When a publishable package changes, include a changeset:

   ```bash
   pnpm changeset
   ```

2. After merge to `main`, the **Release** workflow either:
   - Opens / updates a **Version Packages** PR (consumes changesets, bumps versions, updates changelogs), or
   - Publishes to npm when that Version Packages PR is merged (no remaining changesets).

3. Published packages use `publishConfig.access: public`.

## First release checklist

1. Push this repo to GitHub and set `NPM_TOKEN`.
2. Ensure pending files under `.changeset/` describe the initial release (phases 0–7).
3. Merge to `main` → wait for the Version Packages PR.
4. Review version bumps (expected first cut: `0.1.0` minors from pending changesets).
5. Merge the Version Packages PR → packages publish to npm.

## Manual fallback

```bash
pnpm install
pnpm build
pnpm version-packages   # or: pnpm exec changeset version
# review + commit version/changelog changes
pnpm release            # build + changeset publish
```

Requires a logged-in npm user (`npm login`) with access to `@switchboard/*`.

## Root changelog

[CHANGELOG.md](./CHANGELOG.md) is a high-level project log. Per-package changelogs under `packages/*/CHANGELOG.md` are generated by Changesets and are the source of truth for npm release notes.
